# TABLE//ZERO — V14 URGENT 3D INTERROGATION MASTER DIRECTIVE
# 총괄 목표: 기존 프로젝트 통합 유지 + CASE001 실제 3D 심문 최우선 + 한국형 실사 수사게임의 품질 향상

[0. 수행 원칙]
이 지시서는 기존 V11~V13 및 확정 CASE001 설정에 추가되는 우선순위 지시다. 기존 Unity 프로젝트(Documents\TABLE_ZERO), 서버/AI 코드, 사건 데이터, UI/UX, 현장 조사, 저장 시스템을 삭제하거나 처음부터 재작성하지 말라. 작업 전 프로젝트 구조와 Git 상태를 감사하고 체크포인트를 생성하라. 기존 정상 기능의 회귀 오류를 검사하라. 지금 가장 급한 과제는 '심문실의 정지 이미지를 실제 살아 있는 3D 용의자와 물리 소품이 있는 플레이 화면으로 전환'하는 것이다. 외부 결제·유료 API·크레딧 사용은 사용자 승인 없이 실행하지 말라.

[2. 인물 얼굴 노출 규칙 — 최중요]
프로필/인물기록 화면: 실제 한국인 인물 사진처럼 보이는 선명한 고해상도 정면 또는 약간 비스듬한 얼굴. 회화풍 초상화·그림·AI 카드풍·과도한 보정 금지. 신원 확인이 가능해야 한다.
실제 조사실: 동일한 사람의 리깅된 고품질 3D 인물이지만 눈과 얼굴 위쪽은 조명·자세·머리카락 그림자 안에 자연스럽게 둔다. 입가/턱/손/어깨/의상은 읽혀야 한다. 얼굴 노출을 막기 위한 단순 검정 오버레이 금지. 대사·감정 변화에 따라 고개가 움직여도 얼굴이 갑자기 전부 밝아져서는 안 된다. 표정이나 빛이 유무죄 판정 힌트가 되지 않도록 한다.
프로필 사진과 3D 모델은 얼굴형, 눈·코·입 간격, 헤어스타일, 체형, 복장을 동일하게 검수한다. 다른 얼굴 생성 시 사용자 승인 원본을 임의 교체하지 않는다.

[3. 3D 디지털 휴먼 제작 파이프라인]
먼저 이서연 단 한 명을 실제 심문실에서 시험한다. 3D 제작 방법은 기존 확보 모델, 상용 이용 허가된 고품질 리깅 베이스, Blender 수정, 필요시 Tripo/Meshy 평가 순서로 비교한다. 이미지→3D 출력이 저품질이면 양산을 중단한다. 프로필 사진 한 장만으로 리깅/애니메이션/실사 품질을 보장할 수 없음을 보고한다.
캐릭터 필수: 상체·척추·어깨·목·턱, 양팔/손목/손가락, 눈/눈꺼풀, 얼굴 표정 BlendShape 또는 본, 손·서류·컵의 IK 접점, 앉은 자세에서 의상 관통 방지, 피부 PBR과 자연스러운 머리카락, 좌석의 실제 접촉, 그림자 아래에도 입체감 유지.
첫 검수 포즈: 20초 정지 대기, 느린 호흡, 눈 깜빡임, 질문 듣기, 고개 숙여 자료 보기, 컵 손대기, 자세 바꾸기, 손바닥 책상 접촉. 모션이 없는 상태에서 작동 완료 표시 금지. Higgsfield는 비주얼 참고·연기 콘셉트·제한적인 보조 컷신에 사용 가능하나 생성 영상은 3D 리깅 애니메이션 파일이 아니다. 영상만 루프시켜 실제 상호작용을 대체하지 마라.

[4. 실제 심문 씬 구성]
Unity에서 실제 3D 조사실, 3D 용의자, 의자, 테이블, 서류, 컵, 녹음기, 문, 현실적인 한국 경찰서 조명과 공간음을 구성한다. 화면 한가운데 고품질 3D 용의자를 두고 형사의 눈높이에서 1인칭으로 마주 앉는다. 손이 보이는 형사 플레이어 리그를 유지한다. 셰이더·그림자·반사·그레인은 과장하지 않고, 승인된 실사 톤으로 맞춘다.
용의자 입실·착석과 심문 시작은 3D 씬 전환으로 연결한다. 애니메이션 준비 전에는 정지사진을 인게임 3D로 속이지 말고 미완성 단계로 기록한다.
오브젝트를 단순 큐브/구체/실린더로 만든 뒤 완료라 하지 말라. 임시 충돌체는 렌더링 숨김 가능하지만 보여지는 상업용 사물은 적합한 실제 모델이 필요하다. 라이선스 추적 문서 작성.

[5. AI Acting Director — 대사/행동/물리 분리]
실제 LLM이 용의자별 제한 기억·성격·목표·관계·이전 발언·공개된 증거만 받아 발언/행동 의도를 구조화 출력한다. 사건 진실과 다른 인물의 비공개 정보는 모델에 노출하지 않는다. LLM의 주장은 ClaimLedger에 미검증 주장으로 남기고, 서버 규칙이 허용한 행동만 세계 이벤트로 반영한다.
Unity Acting Director는 AI의 emotion/stance/utterance/gesture proposal을 받아 검증된 애니메이션과 SFX/카메라/소품 충돌로 변환한다. 실제 재생한 애니메이션 이벤트(접촉 타임스탬프)를 기준으로 손·테이블·컵·서류 반응을 동기화한다. 소리/물리/입모양의 타이밍이 어긋나면 불합격. 없는 모션은 거부 후 자연스러운 대체 모션으로 처리하되 누락 기록.
기본 상태: LISTEN, THINK, SPEAK, SILENCE, REVIEW_EVIDENCE, REPOSITION, RESIST, REQUEST_COUNSEL, END_INTERVIEW. 인물별 낮은 강도의 호흡·눈깜빡임·미세한 손 움직임을 비동기 블렌딩하며 반복 주기를 랜덤처럼 보이되 인과와 쿨다운이 있는 방식으로 제어. 모든 3초마다 같은 시선 회피 금지. 용의자의 행동이 유죄 여부를 암시하는 규칙 금지.

[6. 우선 구현할 핵심 심문 시퀀스]
A. 호출 → 복도/문/의자 소리 → 실제 입실/착석 → 녹음 시작 → 플레이어 조작과 질문 입력 활성화
B. 대기 20초: 어깨 호흡, 시선, 작은 자세 변화로 정지 마네킹 느낌 제거
C. 자유 질문: 플레이어가 직접 타이핑 또는 마이크 음성 인식 → 인식문 확인 → 전송 → 실제 LLM 생성 → 말하기 전 침묵/호흡 → TTS/립싱크/움직임 연기
D. 증거 제시: UI 창만 띄우지 말고 플레이어 손이 실제 종이나 사진을 테이블 위에 놓거나 밀어 준다 → 용의자 시선 이동 → 자료를 보거나 거부 → AI 응답
E. 진술 모순: 증거로 입증되지 않은 내용은 진실로 승격 금지, 인물이 반문·부분 인정·변명·침묵 중 정당한 선택을 한다
F. 플레이어 책상 내리치기: 전용 손 모션 → 접촉 프레임의 충돌음/컵 미세 반응 → 용의자별 항의·방어·침묵 → 절차상 불이익·심문 시간 감소. 무조건 자백 금지
G. 면담 종료: 신중한 대사/태도 → 자리 정리·퇴실 또는 남아서 질문 → 실제 AI 자율 후속 행동이 사건 세계에 반영
H. 성공/오인 지목/증거 부족/수사 중단 각각의 후폭풍 연출과 기록 업데이트

[7. 한국어 실제 사람 같은 연기]
번역투, 훈계조, 유사 AI 챗봇 말투, 똑같이 반복되는 감정 묘사·욕설 금지. 직업·연령·관계에 맞는 한국어 높임말과 호칭, 자연스러운 말 끊김, 대답 회피, 짧은 침묵, 문장 길이 편차를 인물마다 정의한다. 실제 게임 대사의 끝 마침표는 제거하되 감정 표시는 배우 연기와 사운드 중심. 재생 실패, 인식 불확실 시 허위 답변 금지.

[8. UX 핵심 — 사람을 가리지 않는 UI]
심문 중 기본 화면은 실제 인물과 테이블이 주인공. 현재 상시 노출된 좌우 큰 패널·행동 메뉴·증거 블랙 패널을 기본 숨김. 상단 작은 사건정보/녹음 상태 + 하단 한 줄 자연어 입력·마이크·전송과 필요할 때만 펼치는 증거/진술/행동/기록. 대사의 청취 중간엔 불필요한 메뉴 자동 표시 금지. 일반 텍스트는 1080p에서 실제 읽을 수 있는 크기. 클릭·키보드·마이크 모두 동작해야 하고 설정에서 자막·입력·볼륨·화면 흔들림을 조절한다.
미래형 UI는 증거·사건 시간대조 등의 선택 순간에만 세계 안의 자료처럼 펼쳐지게 한다. 허위 '거짓말 확률'·'공포 87%' 등 감정 게이지 금지.
질문 시간 비용은 추천 질문과 자유 질문의 차이를 작은 밸런스 수치로 조정할 수 있으나, 입력 타이핑 시간·음성 인식 지연·AI 처리 지연에 페널티를 주지 않는다. 중복 제출/통신 실패 시 이중 차감 금지.

[9. 현재 302호 조사 및 다른 작업 유지]
302호 현장 조사, 140개 상호작용 사물 명세, Blender 재질/조명, 현장 손전등/도어락/서랍/화장실, 증거 출처와 확보 이력, 성공·실패 결말, 수사 타임라인 기능을 모두 유지한다. 긴급 우선순위는 실제 3D 심문 씬이지만 현재 잘 작동하는 1인칭 조사와 AI 서버를 퇴보시키지 말라. UI는 호출-심문-현장-수사보고서 전체에서 하나의 고유한 TABLE INDEX 디자인 언어를 사용한다.

[10. 성능·런타임 AI 운영비]
기준 PC Ryzen 7 5700X / RTX 2070 SUPER / RAM32GB에서 1080p 60FPS를 목표로 측정한다. 로컬 LLM 실행 시 GPU 메모리와 GPU 프레임을 함께 점검한다. Ollama 개발용, llama.cpp 등 출시용 로컬 런타임 검토. 유료 API는 기본 비활성. 모델 추론/음성 인식/TTS는 메인 렌더 스레드를 막지 않도록 비동기 처리. 렌더링 품질을 떨어뜨리는 조악한 최적화 대신 프로파일링으로 병목 개선. 평균 FPS, 1% Low, GPU/CPU 프레임 시간, VRAM, AI 응답 대기를 실제 빌드에서 기록. 기준 미달을 달성했다고 보고하지 말라.

[11. 필수 테스트와 합격 게이트]
실제 Unity 빌드에서 ① 20초 기본 대기 ② 텍스트 자유 질문 3회 ③ 마이크 질문 1회 ④ 증거 물리 제시 1회 ⑤ 컵 또는 서류 접촉 1회 ⑥ 강압 행동 1회 ⑦ AI의 합법적 항의/면담 종료 1회 ⑧ 종료 후 세계 이벤트 확인까지 연속 플레이 녹화. 최소 2종 질문 순서로 재검증. 가능하면 같은 카메라 앵글로 레퍼런스 이미지/기존 영상/신규 Unity 캡처 비교. 근접 손가락, 머리카락, 피부, 옷 주름, 물체 관통, 프레임 급락, UI 가림, AI 대사 한국어 품질 모두 검수한다.
테스트 단계를 '코드 작성/자동 단위 테스트/Unity 컴파일/Play Mode/빌드 FPS 측정/실사 외관 검수'로 명확히 구분해 보고한다. 3D 모델이 없거나 에셋 라이선스가 확인 안 되면 장애를 기록하고 가능한 코드/씬 테스트는 진행하되 상업용 완료로 표시하지 않는다.

[12. 완료 보고·자동 백업]
바탕화면 TABLE_ZERO_개발현황 폴더에 개발현황.md, 다음AI_인계지시서.md, 변경이력, 에셋 출처·라이선스, 영상/스크린샷/테스트 로그, 마지막 정상 빌드, 다음 작업을 업데이트한다. 매 세션 종료 전 Unity 프로젝트·서버·Blender 원본·3D·이미지·음성·UI·사건데이터·검증자료 전체를 최신 전체 ZIP과 버전별 ZIP으로 압축 및 압축 무결성 검사. 시크릿/토큰은 제외. 현재 작업에서 막히는 부분이 있으면 우회 가능 작업 계속 진행하고, 사용자 승인 필요한 결제만 보류한다.

최종 합격 조건: 용의자 프로필은 얼굴이 보이는 사실적인 사진이고, 심문실의 동일 3D 인물은 얼굴 위쪽을 자연스럽게 어둠에 둔 채 실제로 듣고 생각하고 말하고 움직이며 증거와 물리적으로 상호작용한다. 플레이어의 자유 질문이 사건과 이후 세계 상태를 바꾸고, 화면이 '정지 이미지 위 채팅창'처럼 보이지 않는다. 기존 개발 기능을 보존하면서 이를 실제 Unity 빌드로 검증하라.
