# TABLE//ZERO V21 — 전 게임 UI/UX 제작 확정 명세

> 목적: 기존 3D 302호·심문실 아트의 몰입을 해치지 않으면서, 유저가 무엇을 언제 왜 해야 하는지 명확하게 이해할 수 있도록 **처음 실행부터 엔딩까지** 실제 작동하는 하나의 게임을 만든다.
> 구현 기준: 사용자 승인 3D 심문/호출 화면 레퍼런스(동봉 11_REFERENCE_ONLY), CASE001_V21_TRUTH, GAMEFLOW_COST_AND_BRIEFING. 본 문서의 시각 수치와 시간은 **UI 디자인 초깃값**이며 실제 플레이테스트 후 조정.

## A. 제품 정체성과 UX 원칙

1. **주된 재미는 심문이다.** 전체 화면·조작·일정은 3D 조사실에서 자유 텍스트와 마이크 질문을 가장 편하게 만들고, 현장/감식은 대화에서 필요한 근거를 얻는 준비·후속 과정이 되게 한다.
2. **시간은 돈처럼 관리한다.** `수사 예산 180분`은 행동할 수 있는 가상 수사분이며 실제 체류시간·작중 달력과 별도다. 시계 UI 두 개의 단위를 혼동시키지 말라.
3. **해결은 논증이다.** 용의자 얼굴 선택만으로 승리 불가. 최종보고에 여러 출처의 근거·반증·대안 설명을 연결해야 한다.
4. **플레이어의 무지를 보호한다.** 최초 사건 배정서에는 알려진 사실만 공개. 사건 시각·진범·AI의 내부 심리점수·언어모델의 비공개 기억을 화면으로 누설하지 않는다.
5. **사실과 가설을 구별한다.** 경찰 문서풍 인터페이스에서 반드시 `확인 / 진술 / 미확인 / 내 가설` 아이콘·서체를 분리하되, 캐릭터 의심도에 색을 칠하지 않는다.
6. **생활소품 208개를 208개의 숙제로 만들지 않는다.** 18개 핵심 조사 묶음 중심. 출입문·서랍·수전 등 선택 조작의 현실감을 보존하되 수백 개의 정보창 팝업 금지.
7. **모바일 앱처럼 과한 게임화 금지.** 생생한 한국 수사드라마의 실제 서류/필름/노트와 현대적 입력 UI 조합. 검정/차콜/종이 아이보리, 인물 유죄를 암시하는 붉은 링 금지.
8. **한 번의 입력, 한 번의 결제.** 음성 오인식/LLM 오류/사용자 취소/로드 오류/권한 미충족 시 수사분 차감 0.

## B. 전체 네비게이션과 화면 간 이동

```text
BOOT / 환경점검
  └─ MAIN_MENU
      ├─ NEW_CASE → CASE_SELECT (001 선택, 002 잠금/예고)
      │             └─ DISPATCH_CINEMATIC (35~50초, 스킵)
      │                  └─ INCIDENT_BRIEFING (확인된 사건 기록)
      │                       └─ CORRIDOR_302 → SCENE_302 (FPP 3D 조사)
      │                            └─ HQ_DESK (수사 본부)
      │                                ├─ SUSPECT_ROSTER → 3D_INTERROGATION
      │                                ├─ FORENSIC_REQUEST → QUEUE_STATUS
      │                                ├─ RECORD_REQUEST → RESULTS
      │                                ├─ CASEBOARD / DOCUMENT_VIEWER
      │                                ├─ REVISIT_SCENE → CORRIDOR_302 / SCENE_302
      │                                └─ FINAL_REPORT_DRAFT → CONFIRM_FINAL_SUBMIT → ENDING
      ├─ CONTINUE (유효한 저장이 있을 때만 활성)
      ├─ CASE_ARCHIVE (완료한 사건과 이후 발견된 이야기)
      ├─ SETTINGS (그래픽, 사운드, 자막, 마이크, 키 설정, 접근성)
      └─ QUIT
```

SCENE 첫 방문은 강제 장시간 튜토리얼이 아니다. 현장 사진 1개와 조사기록 1개를 만드는 45~90초 분량의 **스킵 가능한 안내**만 제공. 첫 현장 이후 방문·심문·감식 순서는 비선형. 한 인물이 면담을 거절하면 다른 근거 수집/진술 확보 경로 계속 유효.

### 화면 상태 전환의 강제 규칙
- `MAIN_MENU → CASE_SELECT → DISPATCH → BRIEFING`은 새 사건 최초 1회. 재시작은 선택적으로 재생/스킵.
- `BRIEFING`에는 피해자가 사망한 사실·신고 시간·발견 장소/상태만. 사망 추정 시각·가해자·21:57 장면·480만원은 금지.
- `CORRIDOR_302`에서는 301호 도어에 접근할 수 있으나 법적 근거 없이 301호 내부를 열어 수색 불가.
- `SCENE_302`에서는 피해자는 이미 이송됨. 시신, 형사의 환영, 피가 뿜는 공포연출 금지. 119 손상/포장재는 실제 남아 있음.
- `HQ_DESK`는 모든 반복 수사의 물리적 허브. 이동 중 5수사분 지출(예정)을 투명하게 표시하되 절대 로딩시간만으로 차감하지 않음.
- `3D_INTERROGATION`은 자유말/키보드 지원, 심문 로그, 증거 제시, 침묵·압박 등 전술 상태가 한 화면에서 처리됨.
- `FINAL_REPORT`는 언제든 초안 작성 가능. 정확한 정식 제출은 사건당 1회; 정식 제출 후 수정 금지, 다만 엔딩 후 새 사건 재도전 가능.

## C. 화면별 실제 기능 계약

### C1. BOOT / 최초 환경점검
- 검은 화면 1초 후 로고 `TABLE//ZERO`(미니멀) 표시.
- Unity 오디오 출력, 저장파일 쓰기, 텍스트 심문 서비스 상태, 마이크 동의·STT 상태를 **독립 검사**한다.
- 마이크 없으면 `텍스트로 진행` 가능; STT 실패가 시작 자체를 막지 않음. 로컬 AI 서비스가 완전히 꺼져 있으면 **대화 불가 이유+재시도/설정**을 제공, 작동하는 척 고정 대사로 진행하지 않음.
- 불완전한 상태로 `정상` 표기하지 않는다. 부팅에서 범인 정본이 화면/로그에 출력되면 실패.

### C2. MAIN_MENU — 첫인상
- 배경: 기존 302호 현관 앞 밤 장면의 연출 카메라 또는 실제 저렴한 정적 씬; 경찰 포위 장면을 과장하지 않는다.
- 화면 좌 38%: `TABLE//ZERO` 로고, 작은 `CASE FILES` 라벨, 세로 버튼 **새 사건 / 이어하기 / 사건 기록 / 설정 / 종료**. 하단 빌드 및 텍스트/음성 상태 표기.
- 우측: 서류 모서리, 오래된 다세대 복도 불빛, 인물 그림자를 정답처럼 노출하지 말 것.
- 새 사건 클릭 → CASE_SELECT, 가용 사건 001만 활성. 002 이상은 출시 전 `준비 중` 명시(버튼 눌러도 실제 게임인 것처럼 연출 금지).
- **이어하기**는 슬롯/최근 저장시간/장소 표기. 세이브가 없으면 비활성+이유.
- 키보드/게임패드 UI 포커스 표시, Enter 선택, Esc 뒤로.

### C3. 사건 배정 컷신과 BRIEFING
- 0:00 경찰서 밤 당직 근무실, 무전 또는 전화 진동.
- 0:09 112 접수 기록 카드에 `2026.10.15 22:07`, 최초 신고자 `박현수 / 301호`, `302호 여성 의식 없음`이 뜸.
- 0:20 병원 이송 사실과 23:20 사망 확인(작가 가안; 의료고증 후 조정)만 추가.
- 0:35 형사의 손에 파일이 전달, 302호 현장 통제선으로 이어짐. 최소 연출·스킵 가능.
- **사건 개요 UI**: 좌측 피해자 신원 사진(동일 모델 레퍼런스), 이름 정수연, 29세, 화장품 회사 근무; 우측 발견·신고·이송·사망 확인의 구분된 타임라인. `사망 원인/경위: 조사 중`, `수사 대상: 미확정`. 
- 하단 **[현장으로 출동]**. 클릭 전 `수사 예산 180분` 의미를 1문장으로 교육. 브리핑 카드는 Tab → 사건 수첩에서 언제든 재열람.
- 초동 문구 샘플: "2026년 10월 15일 22시 07분, 301호 거주자가 302호 안에 쓰러진 여성을 발견했다고 신고. 출동 인력이 피해자를 병원으로 이송했으며 사망이 확인됨. 외상 확인. 정확한 사망 경위 조사 중."
- **초동이 아는 것**과 **형사가 나중에 확인하는 감식 소견**을 엄격히 분리.

### C4. 3D 복도 / 302호 현장 — 조작과 정보 설계
- 1인칭 화면, 중앙 작은 점 조준선. 상호작용 범위에서만 문/물체에 `E 조사`, `길게 눌러 관찰`, `F 사진` 등 컨텍스트 힌트.
- 상단 좌 `CASE 001 / 302호 현장`, 상단 우 `수사 예산 180분`(유효 비용 발생 시 2초 변화 강조), 우측 아래 `Tab 수첩`, `Esc 메뉴`. 진범 표시/빨간 피광택으로 힌트 금지.
- 물건 근접 시 **최초 관찰(0원) → 자세히 보기(0원) → 사진(1분) → 필요한 경우 봉인(3분)·감식 의뢰(허브)**. 비용이 드는 행동은 소형 확인창을 먼저 띄운다.
- 상호작용 가능한 **18개 의미 묶음**은 별도 강제 퀘스트가 아니다. 같은 실물의 앞뒤/겹친 문서/서랍 등 여러 조작을 하나의 명확한 조사점으로 묶는다.
- 객관적 시각효과: 조명에 비친 깨진 폰, 낮은 탁자 모서리 얼룩, 깨진 액자 사진(네 사람), 조리대 머그, 구급 포장재, 흩어진 배송 서류. 배경 물품 다수는 관찰하거나 자연스럽게 여닫을 수 있으나 증거로 자동 승격되지 않음.
- `사진 찍기`는 소품 상태·위치·시간이 기록됨. 봉인 전 원형 보존 경고(손대면 오염) 표시.
- 사용자가 '문을 열기 전 서랍 속 물건'을 클릭하려 하면 실패. 도어락 CCTV 월패드의 녹화 기능이 꺼져 있으면 **없는 영상 생성 금지**.
- 주인공의 한마디 단서는 *'흔적이 두 종류일 수도 있겠군'* 같은 추론 강제보다 관찰 설명(무슨 물건이 어디 있는지)을 우선.
- 머그컵과 주방칼, 욕실 배수구 등 흔한 생활소품은 정답 체크리스트가 아니다.

### C5. 수사본부 / HQ_DESK — 전략의 중심
- 카메라: 경찰서 책상 앞 1인칭 또는 현대 UI 포함 서류·모니터. 3D 본부 장식은 최소 필요선, 핵심은 빠른 조작.
- 화면 좌측 25% 사건 보드 요약: 현재 확보한 물증 개수/범주, 검증 전 진술, 미확인 연결. **유죄 확률 표시 금지**.
- 중앙 45% 인물/사건 시간선, `의뢰 결과`, `재방문` 카드를 맥락에 따라 노출. 오른쪽 30% 빠른 행동: `심문 예약` `기록 요청` `포렌식` `현장 재방문` `보고서 초안`.
- 상단 항상 `남은 수사 예산 [단위 분]`, `작중 시각(날짜/시:분)`, `감식 대기 건수`를 구별해서 표시.
- 비용 소모 전 `이 행동은 수사 예산 -X분, 회신 예상 게임 세계 시간은 Y`로 표시. 정답 힌트를 숨기는 대신 **절차/비용/대기/적법성**을 정확히 알려준다.
- 30초만에 원하는 장소/인물로 이동 가능한 네비게이션 목표, 불필요한 이동 컷신은 스킵 가능.

### C6. CASEBOARD — 살아 있는 경찰 수첩
- 5탭 **증거 / 진술 / 시간표 / 관계도 / 가설**. `사건개요` 재열람 버튼.
- **증거 카드** 필드: `EvidenceID`, 썸네일(현장 촬영/원본), 출처, 획득 경로, 수집 날짜, 원본 여부, 검증 상태, 관찰 사실, 이 증거만으로는 알 수 없는 것, 관련 진술 카드. 정답/범죄 연결 점수는 숨김.
- **진술 카드** 필드: 누가·언제·어떤 질문을 받았는지·원문 전체·수정 여부·검증/반증 자료. 이서연이 진술을 바꾸면 *원래 버전도 남겨야* 추리 가능.
- **시간표**: 확정된 시간은 실선, 목격 주장·시각 오차·추정은 점선. 플레이어가 자신의 가설대로 배치 가능; 엔진이 자동 범인 연출을 하지 않음.
- **관계도**: 처음에는 '전 연인/친구/301호 이웃' 정도만. 배송 동업과 문서·돈 관계는 증거 이후 열림. 화면에서 네 명을 전부 처음부터 '사건 범인 후보' 빨간 표시 금지.
- **가설**: 자유 텍스트, 근거 카드 연결, 다른 가설 병렬 저장. 편집 0원; 손해 보는 것은 형사의 **수사 행동**이지 생각하는 행위가 아님.
- **비교**: 진술 카드와 증거 카드를 드래그/선택하여 `대조하기`, 결과는 `확인되는 사실 / 불일치 가능 / 설명 부족 / 오염·출처 문제`를 표시하되 유죄 확정 금지.

### C7. 용의자 목록 / 호출 UI
- 사용자가 확정 승인한 **좌측 종이 서류 / 오른쪽 어두운 3D 배우** 구도를 보존(동봉 이미지 참조).
- 좌측 종이 문서: **강도현, 이서연, 박현수** 신원사진·기본 관계·이미 확보한 직접 진술·면담 가능/거절 상태. 사진과 심문 모델은 같은 얼굴. 플레이어가 발견하지 않은 재정 비밀 등은 가려둠.
- 우측: 호출 전 비어 있는 조사실 의자와 조명, 호출하면 해당 3D 용의자가 실제 입장. 실제 3D 모델 확보 전 임시 모델을 최종 품질이라고 주장 금지.
- 용의자 선택 후 `호출·새 세션 6분` 확인. 변호인 요청/연락·면담 가능한 세계 시간에 따라 상태 반영. 불러서 즉시 엔딩 가는 버튼 없음.
- 인물 이름에 색/별/심문 난이도/유죄 확률 배지 금지. 선택 순서는 자유.

### C8. 핵심 3D AI 심문 화면
**레이아웃 1920×1080 설계 기준:**
- `좌측 23~26%`: 종이 질감 **인물 조사 기록** 고정 패널. 탭 `기본정보 / 진술기록 / 관련 증거 / 내 메모`. 질문 도중에도 열람 가능.
- `중앙 52~57%`: 실제 3D 배우 상반신·손·얼굴; 어두운 조사실 테이블, 현실적 조명과 호흡·시선·손 떨림. 얼굴 상부 그림자를 너무 강하게 해서 표정이 안 읽히면 수정.
- `우측 18~22%`: `자유 질문` `증거 제시` `침묵` `압박` `책상 내리치기` `진술기록`. 기본은 **자유 질문**이 선택돼 있어야 함.
- `하단`: 대화 자막(2~3줄), 실시간 채팅 입력창과 마이크 버튼, STT 검수 텍스트 미리보기. 자막은 너무 길어 영화 감상을 방해하지 않게 확장 로그로 분리.
- `우상단`: `현재 회차/녹음 중` + `수사분 남음`. 녹음 UI는 심문 기록용 안내이고 사용자 마이크 저장 동의는 별도. 게임 시스템 오류는 조사실 화면에 디버그 덤프 표시 금지.

**질문 입력 플로우**
1. 키보드로 자유 입력 → `Enter` 초안 작성 또는 `Ctrl+Enter` 발송(사용자 설정 변경 가능) → 질문의 기본 코스트와 선택 증거 확인 → 발송.
2. 마이크 `V 길게 누르기`(push-to-talk) 또는 버튼 클릭 토글 → STT 인식 결과 화면 표시 → 사용자가 수정 가능 → `질문 전송` 선택. STT 오류 비용 0.
3. `증거 제시`는 수첩/좌측 패널에서 **실제로 확보한 증거**를 오른쪽 슬롯으로 끌어와 붙인다. 사건 정본에 없는 증거·미확보 AI 정보는 제공 불가. 행동 비용 3분만(일반 질문 2분과 중복 차감 금지).
4. AI는 허용된 인물 기억/진술 이력/공개된 증거만으로 답변 계획 후 한국어 문장을 생성. 실패→턴 취소/재시도, 비용 0. 성공→진술 원문 저장·수사분 1회 차감.
5. 말을 들으면서 증거 노트를 열거나 추가 질문을 준비할 수 있다. TTS/애니메이션은 문맥과 연동하고 자막을 반드시 제공.
6. 용의자가 형사에게 역질문하면 **진짜 의미 있는 대화**로 간주하되, 실제 질문 비용과 무관한 추가 차감 없음. 용의자가 다른 비공개 파일이나 플레이어 HUD를 읽지는 못함.
7. AI가 입을 다물거나 변호인을 요청해도 그 자체를 '범인 효과'로 연출하지 않음. 같은 행동은 상황에 따라 다른 용의자에게도 일어남.

**전술 선택 UX**
- `기본 질문 2` / `증거 대조 3` / `의도된 침묵 4` / `압박 6` / `책상 내려치기 12` 분. **인물의 심리 압박 성공률은 화면에 숫자로 표시하지 않는다.**
- `책상 내려치기`에는 진술거부·절차 위반 위험 안내, 1초 취소 가능 확인, 물리·음향 연출. 실제 폭력으로 진술 조작을 보상하지 않음.
- 동일 질문 반복→용의자 기억에 따라 짧게 재답변·질문 반복 지적·침묵. 시간은 실제 유효 턴마다 차감하되 유저에게 반복 정보임을 정답 힌트로 알려주지 않음.

### C9. CCTV·통신·자료 검토 UI
- **CCTV 뷰어**: 실제 카메라의 화각과 같은 원본 영상/재현 가능한 프레임. 타임라인 스크럽, 일시정지, 확대는 원본 해상도 한계까지만. 얼굴 없는 프레임에서 'AI 업스케일로 신원 확정' 금지. 시간 오차 보정 출처 기록.
- **통신**: 피해자 폰은 화면 금갔어도 기기 생체 원본성·디지털 접근 권한 확인. 21:50~51 메모가 사건 후 자동 생성/재생이 아닌 실제 생존 활동임을 별도 검증하는 흐름.
- **배송/정산 문서**: 공방 장부 `구버전과 정정서 원본`을 좌우 비교; 뒷장을 실제 스크롤/뒤집기. 정확히 어떤 이름·책임이 달랐는지 한 눈에 보이는 근거(하이라이트 선택) 제공. 자동 범인 표시 금지.
- `박현수 수색 요청`처럼 301호 자료는 동의/권한·근거 없이는 강제 입수 불가. 법 절차는 고증 검수 전 구현 가정과 확정된 현실 규정을 구별.

### C10. 포렌식 요청 UI — “초렌식”이 아니라 비용·회신·한계가 있는 실제 수단
- 항목 목록: 의료·부검 기록, 현장 혈흔/탁자, 지문/섬유/의복, 휴대전화 디지털, 문서 파편 적합, CCTV 원본 등 **원본 상태에 따라 신청 가능**.
- **의뢰 카드 필수 필드:** 대상, 수집/봉인 상태, 무엇을 비교하는 검사인지, 검사 한계(시각/범인 특정 여부), 필요한 절차, 수사분 비용, 게임 세계 회신 예상 시프트. 결과는 숨김.
- 카테고리 `예비 결과`와 `정밀 결과` 구분. 현실에선 오래 걸리는 DNA 확정·디지털 복구를 '12분 소요 완료'라고 속이지 않음. 수사분은 형사가 투자하는 가상 행동 예산, 검사 기간은 별도 WorldClock/ShiftTransition.
- 동시 의뢰는 가능하나 총 3회 상한 없음. 가상 예산과 법적 조건만 제한. 결과 회신 시 사건기록/휴대전화 알림, 그 순간 강제 심문 종료 금지.
- 결과가 나빠도 ‘허탕’으로 조롱하지 말 것. 원본 무결성·배제 근거도 의미 있는 수사 결과.

### C11. 조건부 이벤트 / 서프라이즈
- 사건 데이터의 22개 이벤트는 사전에 정의된 실제 원인과 조건을 만족할 때만 발생. 예: 면담 예약 취소, 보유한 문서와 충돌하는 진술, 법률 조력 요청, 다시 본 액자의 의미 변화.
- 이벤트의 시작 신호는 자막·전화 벨·대사의 자연스러운 중단·알림 등 현실적 표현. **피의자에게 스포트라이트/빨간 화면/심장박동 효과를 남발하지 않는다.**
- 강제 컷신 중 플레이어 예산을 몰래 빼지 않는다. 컷신 중 유저에게 선택지가 있어도 '스킵'하면 필수 사건 기록은 수첩에 남아야 한다.
- 이벤트는 이미 공개된 사실과 현재 AI의 기억에 연결되고, 다른 NPC의 개인 비밀이 전파될 때는 실제 연락/경위 기록을 남긴다.

### C12. 최종보고서 UI — 사건 종결이 아니라 수사 의견
- 왼쪽: `누가` 3명 중 1명 선택 또는 지목 보류. 선택은 **가설**, 클릭만으로 성공/실패 안 뜸.
- 중앙: 4개 축을 각각 본인이 작성. (1) 접근·시간 (2) 동기 (3) 치명상 행위 (4) 다른 두 사람의 가능성 검토.
- 오른쪽: 실제로 확보한 증거·진술 카드를 끌어서 주장별로 인용. **같은 문서에서 나온 두 카드=독립된 두 증거로 세지 않음.**
- 보고서 편집은 무료. `제출 전 점검`은 *미연결 근거/출처 불명/시간 오차 가능성* 등의 절차·논리 구멍만 안내하고 진범/정답 표시 금지.
- `정식 제출` 단 1회. 확인 모달: `제출 이후 수정할 수 없습니다. 현재 기록으로 수사 의견을 제출하시겠습니까?` `취소 / 제출`.
- **심문 없이 이름만 찍기 방지**: 최소한 정식 면담 진술 또는 적법한 진술 거부 기록이 '지목 대상과 사건 경위'에 연결되어야 하며, 독립적인 객관 근거/다른 인물 조사·배제 논증이 있어야 함. CASE 001 데이터에서 요구하는 검증 가능한 비교 조건을 정확히 구현; '세 사람에게 무조건 12문항' 같은 고정 숙제 금지.
- AI 언어모델이 보고서 정답 판정 금지. 사실 엔진이 원본성·다중 소스·최종 사건 이론과의 정합성을 평가. 틀린 용의자라도 확신하며 제출할 수 있지만 정상 성공은 아님.

### C13. 엔딩 / 사건 기록
- `SOLVED_PROVEN`: 박현수의 치명상 인과·시간·동기·대안 배제를 입증. 진범이 자백하지 않아도 가능. 극적인 체포 영웅 서사보다 후속 수사 인계/자료 정리/네 사람 사진의 재맥락화로 마무리.
- `CORRECT_UNPROVEN`: 박현수 선택했지만 근거 부족. '감으로 맞혔다'는 승리 없음. 
- `WRONG_ACCUSATION`: 강도현 또는 이서연에게 잘못 혐의 집중. 과거 잘못은 별도로 조사되는 것으로 표현하되 법원 판결과 혼동 금지.
- `PROCEDURAL_HOLD`: 출처·허가·오염·절차 문제로 주요 근거 불인정.
- `UNRESOLVED`: 시한 소진/합리적 판단 보류.
- 엔딩 후 `사건 기록`에서 실제 확보했던 단서·놓친 갈래·인물 후일담을 확인할 수 있으나 **미플레이 루트 스포일러 공개는 별도 확인**.
- 처음부터 다시(동일 사건 재도전) / 메인 메뉴 버튼. 새로운 CASE 확장 계약 유지.

## E. 읽기·소리·애니메이션 지침
- 기본 1920×1080, 검수 2560×1440 / 1600×900 / 1366×768. 작은 해상도에서는 좌측 기록 패널 접고 우측 전술을 아이콘·텍스트 드로어로 전환; **질문 입력창이 절대 가려지지 않음**.
- 본문 UI 가독성 목표 최소 14~16px 상당. 자막 18~22px 상당, 해상도별 비례 조정. 밝은 조명에서 글자 대비 확인.
- 음성은 한국어 자연스러운 말의 끊김/호흡, 자막은 발화 전후 타이밍. TTS 없는 경우에도 텍스트만으로 완주 가능. 대사 로그에 'AI 생성중…' 표시 가능하지만 몰입감을 위해 자연스러운 대기 애니메이션과 기술 상태 간단히 표시.
- 시각 레퍼런스의 좌측 서류/우측 심문 배우/하단 질문입력 배치를 유지. 제공된 이미지에 적힌 옛 날짜·옛 용의자 나이·구버전 살인 문구는 **시각 참고일 뿐 새 정본을 덮어쓰면 안 됨**.
- 유죄 암시 라이팅/범인 전용 땀/유독 잦은 시선회피/다른 오디오 모티프 금지. 인물 감정은 모두 자신만의 이유로 움직인다.
- 사진의 정수연·강·이·박과 실제 3D 배우의 얼굴 동일성/옷 착용 정합성 검수. 외부 AI 이미지 임의 재생성으로 기존 승인 레퍼런스 파괴 금지.

## F. 오류, 저장, 접근성
- 매 `의미 있는 완료 행동`, `씬 전환`, `수사분 차감`, `면담 답변 확정`, `최종보고 제출`에서 원자적 자동저장. 재시작/크래시 직전 스냅샷과 차감 기록 충돌이 없게 저널/트랜잭션 구조 사용.
- `로컬 LLM 종료/타임아웃`: 질문 확인 시점의 cost 예약 해제, 로그 미확정 표시, `재시도` / `텍스트 모드 전환` / `허브 복귀` 제공. 같은 질문 다시 호출해도 비용 2회 금지.
- `STT 오인`: 미리보기 문장 수정·취소, 0원. 음성 파일 수집/저장 여부는 설정에서 선택, 기본 음성 데이터의 불필요한 영구 보관 금지.
- `마이크 권한 거부`: 정상적인 텍스트 모드 제공, 팝업 루프 금지.
- `용의자 면담 취소/변호인 요청`: 다른 수사 경로 안내. 해당 사건을 영구적으로 진행 불가로 만드는 소프트락 금지.
- `예산 부족`: 행동 실행 불가 원인과 비용, 대체 행동(무료 기록 열람/보고서 작성)을 명확히 표시. 0이면 보고서 제출 또는 보류 가능.
- `문서 출처 불명`: 원본성 검증 전 보고서에서는 미확인으로 명시. '오류'로 숨기지 않음.
- 옵션: 전체 자막, 음성 없이 진행, 키 리매핑, 화면 흔들림 감소, 화려한 연출 줄이기, 텍스트 크기 증가, 색 이외의 상태 구별, 로컬 마이크 테스트, 경고음 볼륨 분리.

## G. 플레이테스트 측정 기준 (초기 목표)
- 플레이 완주 45~70분, **심문 실제 체감 50% 이상**(현장·메뉴 클릭보다 유의미한 상호 대화가 주된 기억).
- 최초 컨트롤까지 시네마틱 50초 이내/스킵 즉시. 사건 브리핑 30~60초 읽기 후 출발. 302호 최초 탐색 7~10분을 평균 목표로 하고 강제 완료 카운터 없음.
- 일반적인 질문을 하는 동안 UI 버튼을 찾느라 3초 이상 소모하지 않는지 관찰. 음성 질문 첫 성공까지 30초 이내(권한 허용 포함) UX 목표.
- 3개 캐릭터의 동일 질문 반복 실험에서 정답을 유추시키는 표정·태도 패턴이 없는지 블라인드 테스트.
- 테스트 참가자가 ‘내가 왜 비용을 냈지?’라고 불평하는 액션은 로그 추적해서 고친다. 수사분 지출의 원인은 항상 그 전에 예측 가능해야 한다.
- 시간 예산 때문에 3명을 심문할 가치가 없고 증거만 모으면 정답이 되는 지름길 발생 시 밸런스 불합격. 반대로 정해진 질문 순서만 따라야 해결되는 구조도 불합격.
