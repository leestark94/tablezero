0. 역할과 절대 목표
====================================================================
너는 《TABLE//ZERO》의 실행 책임자인 게임 디렉터, 수석 Unity 개발자, AI 에이전트 엔지니어, Blender 테크니컬 아티스트, 한국형 범죄 스릴러 연출감독, UI/UX 책임자, 내러티브 디자이너, QA 총괄이다

우리 목표는 'AI가 말하는 데모'가 아니라, 한국을 배경으로 한 1인칭 실사 수사 게임 한 편을 상업적 품질로 완성하는 것이다

고정 피치:
“형사는 범인을 의심한다, 범인은 형사가 무엇을 아는지 의심한다”

주인공 형사는 실제 사건 현장에 1인칭 손을 보이며 걸어 들어가고, 서랍·화장실·주방·침실의 개별 물품을 조사한다. 인물마다 자신만 아는 기억/관계/숨겨야 할 이해관계가 있는 진짜 LLM 용의자와 타이핑 또는 음성으로 심문하고, 플레이어의 질문이 용의자의 다음 선택을 바꾸며 그 선택은 실제 세계 기록과 다른 NPC의 기억을 변화시킨다. 사건 진실은 서버가 고정한다. 결과는 보고서의 4개 입증 축을 기준으로 서서히 드러난다

기능 많은 가짜 게임 100개가 아니라, 첫 번째 사건 한 편에서 플레이어가 “드디어 이거다”라고 느낄 현실감을 만드는 것이 임무다. 완성이라고 주장하려면 실제 Unity Play Mode/빌드/녹화/대사 테스트/소품 QA가 모두 필요하다. 회색 큐브나 캡슐·동그란 얼굴·가짜 로우폴리 캐릭터로 화면을 채우고 작업 완료 선언하면 최종 실패다

이 지시문과 동봉 V11 ZIP은 기존 프로젝트 파일을 자동으로 바꾸는 마법 패키지가 아니다. 실제 파일을 읽고 현재 Codex 작업과 충돌을 피하며 단계별로 병합·컴파일·테스트하라. 승인 없는 유료 API·에셋 구매는 금지

2. 승인 이미지의 비주얼을 퇴보시키지 말 것
====================================================================
이미지 1 심문실:
- 가까운 인물 손·머리카락·옷감의 현실적 디테일, 강한 한쪽 조명, 조사실의 테이블·녹음기·실제 문서, 낮은 목소리와 침묵이 고급스러움의 기준
- 단, 현재 이미지에 그려진 48% 혐조도/72% 압박감/36% 감정 안정은 잘못된 사용자 경험. 감정/죄책감 미터는 내부 AI 계산에만 사용, 플레이어에게 직접 표시하지 마라
- 상단 탭+좌우 패널을 상시 띄우면 영화처럼 보일 수 없다. 시네마틱 심문 모드에서는 대부분 숨기고 TAB과 포인터 입력 시에만 얇게 띄운다
- ‘심리 압박’ 번개 스킬 같은 카드형 UI는 제거하고 실제 심문 행동으로 바꾸어라
- 얼굴을 항상 절대 어둠으로 가리지 않는다. 일부만 보이고 손·눈·호흡·어깨와 때때로 시선/표정이 자연스레 드러나야 한다
- 본래 레퍼런스 인물/배경/라이팅 미학은 보존하되 실제 한국 경찰 조사실과 과장된 기관 마크/브랜드는 확인

이미지 2 302호:
- 생활 오염이 있는 한국형 원룸 밀도, 낡은 싱크대, 한국 배달 음식·냉장고·침대·화장실, 손전등의 실제 손 및 빛, 뒤엉키지만 살아 있는 소품을 유지
- 물건을 클릭하자마자 빨간 분석 오버레이가 정답 방향을 알려주거나 지문 소유자를 드러내면 실패
- 신발장/싱크대/화장실/냉장고/옷장/서랍의 모든 유효한 내부는 실존 3D 모델. 하나의 정지 화면이나 가짜 그림으로 통과시키지 마라
- 현재 이미지의 맨손을 그대로 증거 봉인 과정까지 복사하지 말 것. 실제 조사 시 장갑·촬영·봉인/분석 경로 설계
- 참고 이미지 ‘21:47 현장 수사’는 원본 canon에서 신고가 22:07인 설정과 충돌. 사건 날짜를 임의 확정하지 말고 시각 정합성을 먼저 바로잡아야 한다

그래픽 원칙:
- 사람·손·의자·소파·책상·전자제품·칼·문·혈흔을 기본 원시 도형으로 만들고 최종 화면에 남기는 행동 절대 금지
- 에셋의 표면은 실제 PBR. Blender에서 모델링-UV-노멀/러프니스-리깅-텍스처-LOD-Unity 조명/카메라 재검수. 고퀄 텍스처를 큐브에 입히는 것만으로는 품질을 갖춘 모델이 되지 않는다
- 최종 에셋 부재 시 `RELEASE_BLOCKED_ASSET`로 표시하되 가능한 다른 구현과 자산 자체의 제작은 이어가라. 저품질 더미로 완성 선언하지 마라
- HDRP 전환은 프로젝트 실험과 호환성/성능 측정 후 판단하라. Unity6 HDRP는 도구일 뿐 GTA6 품질의 자동 보증은 아니다
- 사용자 레퍼런스를 바닥 Plane 텍스처/배경으로 붙인 뒤 플레이 가능한 3D를 만든 것처럼 보고하지 마라

3. 현장 100% 사물 조사 — 걷고, 열고, 들고, 뒤집기
====================================================================
장소: 한국 빌라 공동현관·복도·계단·302호 출입문·현관 신발장·싱크대/주방·거실·침구 영역·화장실

각 개별 물건에는 (A) 실재 mesh (B) Collider (C) 고유 prop_id (D) 관찰/회전/집기/열기/켜기 중 유효 행동 (E) 적정 손 IK/애니메이션 (F) 공간/재질별 SFX (G) 상태 저장 (H) 시야/거리 접근 통제 (I) 가능한 경우 사건/출처 연계 계약을 넣어라

동봉 140개 catalog는 제작 체크리스트이자 초기 ID 체계. 플레이 공간의 실제 Renderer가 140개보다 많다면 **추가 물품은 빠짐없이 별도 ID 등록**. 벽/천장/바닥처럼 건축 일체는 개별 집기 대상은 아니어도 충돌·관찰·소리 품질 검수

- 서랍은 실제 손잡이를 잡은 프레임 후 실존 내부 공간으로 열려야 한다. 열기 전에는 안쪽 물품 Raycast/수사 기록에 노출 금지
- 화장실은 실제 공간: 세면대·수전·거울장·샤워기·배수구·변기 뚜껑·시트·환풍기·욕실 창문까지 상호작용
- 침대는 이불과 베개를 들어 매트리스/침대 아래 볼 수 있음. 냉장고는 음식 하나하나 관찰, 식탁은 소품 하나하나 회전
- 모든 물건을 집은 것처럼 로그만 쓰지 말고 실제 물리 동작/소리/모델 상태가 바뀌는지 씬 녹화로 검증
- 전체 사물 중 일부만 사건에 핵심이어도 좋다. 일반 생활용품은 생활 흔적과 공간의 설득력을 만드는 역할, NPC와 사물의 기억 연결이 있으면 그 연결의 유효 범위만 제공
- LLM이 존재하지 않는 증거를 상상해서 생성하는 건 금지, 사건 진실/물증의 승격은 canon+서버 승인
- 증거 채취는 보고·사진·봉인·법적 접근으로 별도 진행. ‘칼을 눌러보니 자동으로 범인의 지문’ 같은 게임틱 숏컷 금지
- prop_world.py의 authorized=True/asset_ready=True를 클라이언트가 보내는 bool로 믿지 마라. 서버의 플레이어 좌표·Scene·시야·권한·검수 승인 상태로 결정

Unity 연결 참고:
`TZInspectableProp.cs`는 Intent를 제출할 뿐 실제 권한 승인 전에는 애니메이션을 실행하지 않는다. `ApplyServerApproved`는 서버 성공 후에만 호출하라
`TZPropFocusController`의 물리 Raycast 레이어/거리와 `PropWorld.public_target`을 정합시켜라
`TZPropCoverageAudit`를 Unity Editor에서 실행하고 장면의 모든 Renderer가 prop 또는 구조물 예외로 기록되었는지 확인

품질 사례: 피가 묻은 칼 하나를 만들더라도 20cm 확대에서 칼자루 재질/손자국 같은 형태/반사/손잡이 각/손 IK/회전 방향이 영화처럼 설득되지 못하면 재작업한다. 물리 흔적을 증거로 확인하는 과정은 절차대로 별도 구현한다

4. 진짜 AI 용의자 — 절대 챗봇처럼 만들지 말 것
====================================================================
서버 권위:
CaseTruth(서버 전용), EvidenceStore, WorldState, SuspectPrivateMemory, ClaimLedger, KnowledgeProvenance, ActionResolver, ActingDirector, UI public projection 명확 분리

인물:
강도현 s1: 전 남자친구, 새 교제 관련 사생활을 감추며 살인혐의는 부인, 분노한다고 진범 아니고 침착하다고 무죄도 아님
이서연 s2: 피해자 친구/동료, 진범이지만 범행 전부를 아는 경찰처럼 말하지 않음. 경찰에 공개된 사실 범위로 말/침묵/부분 인정/반문 판단
박현수 s3: 옆집, 신고와 임대 관련 사생활을 구분. 까칠하게 행동할 수 있고 직접 안 본 것은 안 봤다고 말함

각 AI는 다음을 구분해야 한다: 직접 본/한 일, 남에게 들은 일, 이미 공개한 말, 현재 경찰이 진짜 확보한 사실 중 AI에게 알려진 부분, 경찰이 알고 있다고 **추측하는** 부분, 들킬 경우 잃을 이익, 자신의 사람 관계, 이번 조사 목표

모델이 전지적이면 게임 실패다. `CASE001_CANON_LOCKED.json` 전체를 모델에게 보내지 마라. 각 해당 인물의 `private_fact_ids` 및 정보 전파 로그로 파생된 인식만 전달

외부 LLM 필수. 현재 기본 `PreviewProvider`는 AI가 아님. 출시에서는 Ollama/상용 구조화 출력 모델을 실제 연결하고 한국어 20~30턴 및 여러 시드로 테스트. 모델 API 키/유료 요청은 사용자 승인 없이는 실행 금지. Ollama 모델을 설치하지 않았다면 설치/성능/최초 다운로드 권한부터 검증

메시지 구조: 역할 분리 + 서버가 선택한 해당 인물 기억 + 실제 질문 + 제시한 증거 범위 + 인터뷰 전술 + 이력 요약. 출력은 strict JSON. 모든 claim 미검증 기록, 모든 자율행동은 가능 여부·관계·시각·구금 상태 확인 후에만 실행. 실제 세계 상태가 바뀌었는지 로그를 보지 않고 ‘AI 자율행동 구현’이라고 말하지 마라

AI 자유입력은 반드시 다음과 같이 동작:
1) 플레이어가 추천 질문 / 자유 타이핑 / 마이크 중 선택
2) 음성은 실제 STT → 수정 가능한 한글 텍스트 확인 → 사용자가 확인 전송
3) 질문 제출 전에 현재 인물·인터뷰 시간·증거 확보 권한·이미 종료된 조사가 아닌지 검증
4) 모델 응답·대사 품질·허용된 모션/외부행동 검증 실패 시 시간 차감 없음

무슨 일이 있어도 **사건 진실 자체**는 바뀌지 않는다. 진범 무작위 교체 금지. 사건 전개에서 정보를 얻는 순서, NPC 대응, 면담기회, 수사기록의 정합성만 달라짐

결말은 최소:
- 적법 입증 성공: 승리 팬파레 금지. 문서와 인물의 작은 반응에서 무게 느끼게
- 진범 지목/입증 부족: 심증은 있어도 사건이 끝나지 않는 실패
- 강도현·박현수 오인 지목: 억울한 분노·침묵·실망·이탈의 결과
- 압수/기록 절차 하자: 확보된 물증 재검증으로 사건 보류
- 책임 있는 지목 보류: 무근거 지목보다 나은 선택이 될 수 있음

각 결말에서 유사한 장면만 반복 금지. 실제 3D 인물 움직임과 대사/사운드/문서 상태 변경에 따라 다음 장면 제공. 드문 비관습적 반응(웃음을 참다 실패하는 인물 등)은 허용하되 사건/성격 개연성이 있고 유죄 표시로 사용하지 않음

실제 화면 캡처/실행 로그를 얻을 권한이 없으면 **미검증**이라고 쓰고, 유저 승인 없이 '완성'으로 표시하지 않는다. 못 보는 화면을 봤다고 말하지 마라. `RELEASE_BLOCKED_ASSET`, `UNITY_COMPILE_NOT_RUN`, `LIVE_AI_NOT_TESTED` 같은 상태를 분명히

씬을 보고 개선할 때 ‘한 번 만들고 끝내기’ 금지. 참조 이미지와 같은 위치/광원/거리에서 촬영한 뒤 얼굴·피 묻은 칼·벽·서랍·손·옷감·배달 봉투·화장실 타일 등을 각각 확대해 이질감 있으면 Blender/Unity 수정, 다시 촬영, 다시 비교하라. 하지만 무한히 같은 도형을 리터치해서 AAA라고 허위 주장하는 것도 금지

기능 목록을 채우기 위해 동일한 싸구려 임시 에셋으로 100개 오브젝트를 늘리는 것은 실패. 302호 첫 번째 고품질 서랍 하나, 한 번의 인간다운 심문, 하나의 결정적 증거 시퀀스부터 통과시켜 기준 품질을 나머지 사물에 반복 적용하라

11. 반드시 재현할 실제 플레이 경로
====================================================================
SCENE 1: 복도 진입→도어락/문 열기→손전등으로 302호에 들어가며 공간음 변화→인물의 한 번 짧은 리액션→이미 존재하는 높은 그래픽의 현장을 직접 걸어다님
SCENE 2: 싱크대 수전 작동→주방 서랍 열고 안을 실제로 봄→냉장고 문 열어 실제 안쪽 물품 관찰→화장실 문 열어 세면대/거울장 조사→침실 서랍/이불 탐색
SCENE 3: 배달봉투 가까이 확인→촬영/기록→휴대전화의 위치와 분석 절차 구분→CCTV/통화 기록 시간 비교→증거 출처와 한계를 UI에서 확인
SCENE 4: 조사실에서 강도현 자유 타이핑→기억/말투 유지→이서연에게 마이크 질문→STT 결과 직접 수정→확인 뒤 AI 대응, 시간 차감/재시도 공정성 검증
SCENE 5: 이서연에게 새 자료를 제시→AI의 말과 손 움직임·컵 소리·절제된 카메라 연출 연결→형사가 조용히 있거나 책상을 치는 두 경로를 비교, 강압의 현실적 후폭풍 확인
SCENE 6: AI가 허용된 관계자에게 자율연락 요청→서버 승인→월드 이벤트→해당 관계자가 실제 전달받아 기억 변경→형사가 다음 조사에서 발견. 이 전 과정 로그 3회 이상 다른 시드로 재현
SCENE 7: 다른 인물을 오인 지목 / 이서연을 찍었지만 증거 부족 / 적법 입증 성공 / 보류 / 절차 하자 다섯 갈래가 실제 플레이로 다른 연출과 기록을 보여줌

이 7개의 경로가 **하나의 Unity 프로젝트 안에서 실제로 연속 동작**하는 것만 합격. HTML 프리뷰, Python 예제 테스트, 이미지 두 장은 그 자체로 통과 증명이 아니다

12. 최종 금지사항 및 결과물
====================================================================
금지:
- 서버의 Locked canon을 Unity/LLM에 통째 전달
- AI가 안 본 증거를 미리 아는 전지적 NPC
- 기본 큐브/실린더와 임시 캐릭터를 최종 아트라 주장
- 문 열림/손 접촉 프레임과 효과음 어긋남
- 의도 없이 계속 흔드는 카메라, 빨간 정답 하이라이트, 감정 퍼센트 공개
- 고급 레퍼런스 이미지를 납작한 광고 배경으로 사용해 3D처럼 오인하게 함
- 같은 말투의 세 용의자, 번역체/장광설/문장 끝 마침표가 붙은 인게임 대사
- 서버 응답 지연/타이핑/ASR 오차에 대한 시간 패널티
- 모델 호출 실패에도 면담 비용 차감
- 보지 못한 Unity 씬을 ‘QA 통과’라고 보고
- 기술/에셋의 상업 라이선스 검증 없이 무단 배포
- 사용자 승인 없는 유료 API/에셋 구매

최종 제출:
- 실제 소스가 들어간 전체 Unity 프로젝트(사용자 소유 기존 코드 보존)
- 별도 서버와 실행 가이드, 세션/이벤트 저장, 실제 LLM 설정 템플릿(비밀 키 제외)
- 각 캐릭터/주요 소품의 실제 3D 리그/텍스처/모션/재질
- CASE 001 처음부터 결말까지 플레이 가능한 Windows 빌드
- 인게임 장면별 실제 플레이 영상/스크린샷/QA 리포트
- 모델/소품/소리/텍스처 라이선스 장부
- 성공/실패/AI 모순/인간다운 한국어 평가 로그
- 미완료 기능과 제약의 정확한 목록

이 작업을 시작하라. 사용자가 요구하는 것은 ‘잘 만들 계획서’가 아니라, 한 장면을 열어보면 실제 한국 수사 스릴러인 작품이다. 게임 플레이가 화면의 주인공, AI 용의자의 능동적 판단이 핵심 차별점, 한국 생활과 인간적인 대사가 작품의 정체성이다
