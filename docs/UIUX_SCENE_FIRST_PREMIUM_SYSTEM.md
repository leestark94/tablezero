# TABLE//ZERO — UI/UX 최종 아트 디렉션 V11

## 최종 판단
두 레퍼런스 이미지를 현재 최고의 비주얼 기준으로 잠근다. *더 발전*은 UI를 계속 얹는 것이 아니라 유저가 실제 환경을 보고 듣고 조작하게 하는 것이다. 미완성 카드형 SF HUD를 그대로 늘리지 말 것

## 이름 붙일 수 있는 고유 시스템: TABLE INDEX
CASE DESK는 ‘증거 도감’이 아니라 경찰 기록을 현실 테이블에서 직접 다루는 **TABLE INDEX**다. 이건 패널의 브랜딩이지 마법 스캐너가 아니다. 플레이어는 3D 물건을 손으로 들고, 열린 기록에서 **관찰 사실 / 원본 출처 / 타인의 진술 / 감정 회신**이라는 네 층을 선택해 겹쳐본다

## 4개 화면 상태

### A / 현장 몰입 모드 (기본)
- 화면의 90% 이상은 3D 공간과 1인칭 손
- 고정 HUD: 사건명 미세 텍스트, 부드러운 상호작용 표식 필요할 때만. 큰 목록·진행률·심리 바 없음
- 물건에 1.7m 안팎 접근하면 손/카메라 자세가 자연스럽게 반응. 실제 Raycast 가능한 대상만 표시
- 증거에 가까워도 과장된 파란 아웃라인 금지. 필요 시 대비가 낮은 미세 모서리 표시 또는 우측 하단 `E 조사`
- 현장 위계: 발소리/복도 센서등/냉장고/통화기록/혈흔/서랍. 모든 것을 한 번에 UI로 설명하지 않음

### B / 개별 물건 세밀 조사
- 실제 두 손을 사용해 물건을 들어 회전/가까이 보기. 봉인물인 경우 직접 접촉 대신 사진/도구 절차
- 좌측 좁은 ‘관찰’ 레이어: 관찰·촬영·채취 가능 여부/절차, 출처. 결론을 과장하지 않음
- 중요한 글자/송장/제품 날짜는 1440p에서도 읽을 수 있는 실제 TextMeshPro/고해상도 디테일
- 회전/확대 후 원래 위치 복귀, 플레이어 동선과 서랍 상태 보존

### C / 조사실 시네마틱
- 기본: 용의자, 테이블, 자료, 플레이어의 손. 상단 바/좌측 수치 패널/우측 5개 큰 버튼은 숨기거나 매우 얇게
- 질문 입력창: 한 줄에 자연어, 마이크 누르기. 입력 중에는 게임 내 심문 시간 멈춤(텍스트/음성 인식 지연 공정성)
- 추천 질문: 타이핑 보조. 한번에 3개 이하, 더 보기 기능. 추천 질문도 ‘정답’을 자동 선택해 주지 않음
- 행동 메뉴를 펼치면 '침묵 유지', '자료 조용히 놓기', '질문 다시 하기', '목소리 높이기', '책상 내려치기', '변호인 요청에 응답' 등 실제 면담 태도로 표시. 번개 아이콘 스킬/감정 퍼센트 금지
- 플레이어가 입력 완료하면 UI가 테이블 아래로 미세하게 사라지고, 인물의 답을 먼저 보게 한다

### D / 수사기록면 TABLE INDEX
- TAB: 게임의 세계와 연결된 수사 폴더/기록 뷰로 전환, 0.2~0.4초 후보, 실제 오디오/손·카메라 연출과 동기화
- 사건 개요 → 원본 자료 → 진술 기록 → 시간 대조 → 보고서. 각 탭은 다른 시스템이 아니라 같은 출처 레이어
- 자료 비교: 두 기록을 동시에 볼 수 있고, 선택한 시간대만 강조. 자동 ‘거짓말’ 빨간 번개 효과 금지
- UI 텍스트: 복잡한 표보다 문장의 출처와 시간의 불확실성이 먼저 보이도록 설계
- 대화 기록: 실제 녹음 시각, 사람, 문장, 형사가 공개한 증거를 모아 당시 맥락을 확인
- 특정 대사 선택 → 당시 세계 정보가 무엇이었는지 되짚기. AI 캐릭터의 비공개 생각이나 정답 정보는 표시하지 않음

## 비주얼 토큰 (초기값)
- 배경 #080A0D / 패널 #10141A / 텍스트 #E9E8E3 / 보조 #A7ABB0 / 브론즈 #B98D5B / 적색 강조 #C24D55
- 유일한 강조색은 핵심 행동/녹음 중 상태. 빨간색을 AI 거짓말 색으로 사용하지 않음
- 표준 16:9 1920×1080, 1440p, 21:9, 최소 UI scale 100/125/150% QA
- 실제 한국어 본문 14~17px 기준, UI 밀도가 높아지면 텍스트 높이보다 한 줄 길이와 줄 간격부터 재조정
- 인물의 시선 방향·손 소품이 중심이다. 3D 전면 큰 창 대신 화면 끝 얇은 입력 바 선호
- 색각 이상·화면 흔들림 감소·자막 크기·음성 입력 불가 폴백 필수

## UI 행동별 완성 연출 계약
| 행동 | 물리/사운드/시각 흐름 | 오류/중단 |
|---|---|---|
| TAB 열기 | 손이 수사 파일 쪽으로 이동 → 화면 주변 어둡게 → 정보 정렬 | 모션 없는 경우 장난감 파일 비행 애니메이션 만들지 말고 즉시 안정적 패널 |
| 물건 조사 | 손이 물건을 짚음 → 관찰 포즈 → 포커스 텍스트 | Collider 없는 물건에는 ‘조사 가능’ 표시 금지 |
| 서랍 열기 | 손잡이 IK 접촉 → 서랍 Joint/애니메이션 → 안쪽 실제 물건 표시 | 서버 거부 시 서랍 열림 재생 금지 |
| 두 기록 비교 | 자료 한 장씩 정렬 → 시간선이 대응하는 조각을 보여줌 → 플레이어 결정 대기 | 데이터 불충분 시 미확인 유지 |
| 텍스트 질문 | 키보드 입력 무료 → 확인 → 줄이 접히며 카메라 인물로 이동 | AI 실패 시 차감 없이 재시도 |
| 마이크 질문 | 녹음/사용 안내 → 음성 인식 → 플레이어가 정정/확인 → 실제 AI 응답 | STT 잘못 들으면 취소, 불이익 없음 |
| 증거 제시 | 형사 손이 실제 사진/서류를 밀어 놓음 → 용의자가 보는 모션 → 대응 | 증거 없는 경우 조작 불가, AI가 보지 않은 내용을 알게 하지 않음 |
| 책상 치기 | 손→접촉 프레임→컵 물리→녹음 충격음→인물 반응→절차 리스크 | rig/소리/충돌 없으면 **버튼 비활성**, 임시 효과로 대체 금지 |
| 최종 보고 | 보고서 검토 → 확인 → 접수/보완 연출 → 후폭풍 | 성공을 음악이나 UI 색으로 선공개하지 않음 |

## 인게임 UI 개발 품질 게이트
- 단순 HTML 프리뷰/이미지 합성으로 Unity UI 완성 보고 금지
- UI Toolkit + 필요한 부분만 uGUI/WorldSpace Canvas. 실제 원본 프로젝트 버전의 지원 범위 확인
- 모든 입력은 마우스, 키보드, gamepad 중 지원 대상을 명확히, 포커스/뒤로 가기/취소/드래그 및 네트워크 재시도 테스트
- 사운드 볼륨 변화/블러 강도/애니메이션 길이는 실제 3D 화면에서 사람의 눈으로 검수
- 화면 A/B 리그레션: 두 사용자 제공 이미지보다 인물 모델, 배경, 조명이 한 단계라도 싸보이면 **보류**. 단순히 패널을 더 화려하게 만들어 이를 덮는 행위 금지
- ‘UI는 독창적’이라고 문자만 선언하는 건 무효. 입력→물체→기록→재수사라는 인과적 연결이 실제 플레이에 있어야 한다
