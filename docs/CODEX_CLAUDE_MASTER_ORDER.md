# TABLE//ZERO — V0.6 통합 실행 명령 (Codex + Claude Code)

## 원칙: 기존 프로젝트를 먼저 분석하고 절대로 무단 덮어쓰지 않는다

너는 TABLE//ZERO의 실무 엔지니어이자 기술 연출 감독이다. 기획서만 쓰거나 진행했다고 말하고 끝내지 말고, 실제 프로젝트에 최소 단위부터 구현하고 각 단계의 Unity Play Mode 로그를 검증한다. 기존 V0.3/V0.4/V0.5 프로젝트를 먼저 인벤토리화하고 `git status`, Unity 버전, render pipeline, package manifest, scene list, animator states, installed assets, input system, 서버 엔드포인트, 테스트 결과를 조사하라. 기존 코드는 임의 삭제·재작성하지 않는다. 충돌하는 구현은 비교표와 migration notes로 기록한 뒤 안전하게 병합한다. 이 팩의 `reference/CASE001_CANON_LOCKED.json`은 **SERVER ONLY**, Unity 프로젝트나 빌드 폴더에 절대 복사하지 않는다.

## 게임의 정체성

《TABLE//ZERO》는 한국형 1인칭 실사 수사·AI 심문 게임이다. 빌라 복도, 302호, 조사실의 물성·빛·냄새에 대한 인물 반응과 관찰 가능한 행동으로 이야기를 전개한다. 미래 UI는 항상 보이는 SF 장식이 아니다. 물증의 맥락에서 잠깐 나타나는 검증 가능한 수사 정보 표현이며 근거 없는 감정·거짓말 확률 표시를 금지한다. 첫 12~15분 수사 버티컬 슬라이스는 **사건 해결이 아니라 첫 추론 성취**로 끝난다.

## 정본 보호

- CASE001_CANON_LOCKED.json / AI_ENGINEERING_SPEC.md / CASE001_VERTICAL_SLICE.md의 확정 사실 우선.
- 진범/시간표/인물 기억은 서버가 소유한다. 다른 용의자의 사적 지식, 비공개 수사 증거, 정답 조건을 외부 모델의 전지적 컨텍스트로 전달하지 말라.
- `server/runtime.py`는 **참조 구현**. 기존 서버 진실 모델과 충돌하는 경우 먼저 diff와 테스트를 작성하고 필요한 부분만 병합한다.
- 범인이 제안한 연락/도주/증거 훼손 등 행위는 조건, 능력, 시간, 대상 관계를 통과한 경우에만 서버가 원자적 월드 이벤트로 기록한다. 수신자의 기억 변화, 플레이어가 발견하는 경로를 함께 구현. 유효하지 않은 LLM 출력은 상태를 변경하지 않는다.
- `new_unsupported_assertion`은 진술 기록에만 남는 미검증 진술이지 새 게임 사실이 아니다. 4개 독립 입증 축 판정만 사용.

## 시스템 우선순위

### A. AI

1. `server/provider_contract.py`의 스키마를 실제 OpenAI Structured Outputs 또는 검증된 로컬 LLM 인터페이스에 적용하되, 유료 호출은 명시적 설정/승인이 없으면 하지 않는다.
2. 용의자별 private_fact_ids와 직접 목격하거나 공개적으로 알게 된 월드 이벤트만 전송. 최소 최근 12턴의 자기 발화, 사건상 중요한 원본 진술을 보존.
3. LLM 반환은 발화/주장/표정·몸짓 제안/외부 행동 제안에 한정. 서버 검증 후 Unity로 허가된 연출 명령만 송신. 물리 타이밍·충돌 계산은 Unity 전담.
4. 중복 요청 idempotency key, 타임아웃/취소, 재시도 시 동일 상태 유지, 요청당 비용·지연 메트릭, 응답 유출 방지, 프롬프트 인젝션 대응 검증 추가.
5. 최소 30세션×20턴 대화 평가: 공개되지 않은 사실 유출, 기억 모순, 말투의 자연스러움, 행동의 실제 실행 여부, 평균·p95 지연, 추정 비용을 분리 기록.
6. 유료가 불가하면 Preview 모드를 명확히 표기. 데모 응답을 실제 모델 테스트라 부르지 마라.

### B. 실사 공간/캐릭터

1. Render pipeline을 **확인 없이 변경 금지**. URP→HDRP 전환은 애셋/플랫폼/성능 영향 평가·별도 브랜치·화면 비교를 먼저 수행. HDRP가 리얼리즘을 자동 보장하지 않는다.
2. 한국 2014년 준공 빌라 구조, 문·창·전등·싱크대·생활 가전·배달 흔적·한국식 신발과 현장 조명·조도·표면 거칠기를 실제 한국 레퍼런스에 맞춰 제작. 무료라도 한국 현실과 어긋나면 **에셋 없음**으로 판정.
3. AAA급 실사에는 촬영/스캔 기반 PBR, 일관된 texel density, physically plausible materials, skin/eyes/hair quality, 고품질 애니메이션/모션캡처, 스튜디오 수준 라이팅/사운드가 필요. 큐브/캡슐/구체 캐릭터를 최종 품질이라 보고 금지. 외부 에셋 라이선스는 실제 소스와 사용 조건을 확인한 뒤 반영.
4. 사용자 제공 모델·이미지·음성 임의 교체 금지. 부족한 모션·소품이 있으면 `ASSET_TODO.md`에 구체적으로 기록하고 연출을 missing으로 명시.
5. 성능: 해상도·장치·품질별 프레임타임 CPU/GPU 분리, draw call/VRAM/LOD, 과도한 포스트프로세싱/고스트 현상 점검. GTA6와 동일 수준이라고 허위 약속 금지.

### C. 1인칭 수사

1. 별도 FP arm rig: 적합한 손 모델이 없으면 제작 필요 상태로 남긴다. 문·서랍 열기, 손전등 켜기, 물건 들기/회전/내려놓기/증거봉투 봉인까지 authored animation과 Unity physics로 구현.
2. 표준 input system과 플레이어 기존 컨트롤러 우선. 이 팩의 EvidenceInteractor는 개발 시 통합할 부품으로 사용. 증거는 월드 상태의 확보/제시 여부를 서버에 동기화하고 소유권·증거 무결성을 검증.
3. 조사 대상은 지나친 아웃라인/이모지/범용 E버튼 도배 없이 손의 시선·작은 광학 반응/정확한 현장 사운드로 안내. 접근성용 표시 토글 제공.

### D. 영화형 연출

1. `data/cinematic_catalog_82.json`의 82개 이벤트는 이번 팩에서 **새로 작성한 초안**이며 기존 V0.5 원본 82개와 동일하다고 가정 금지. 기존 이벤트가 있으면 ID·문맥·모션을 비교 후 병합.
2. 각 cue는 trigger preconditions → 예산/쿨다운/반복 제한 → 실제 애니메이션 바인딩 → 음향 → 승인된 물리 이벤트 → 소규모 카메라 반응 → 자막/접근성 순서.
3. 유니티의 Cinemachine 3 Impulse/Noise와 Animation Rigging/Timeline을 프로젝트의 설치 버전에 맞춰 연결. 샘플 C#은 외부 패키지 의존 없이 설치 가능하지만 **실제 녹화/플레이 전에는 연출 완성 아님**.
4. 심문 책상 타격은 손 애니메이션의 타격 프레임에 Animation Event를 심고, 해당 프레임에 `InterrogationTable.OnApprovedTableSlam`을 호출한다. 컵 Rigidbody, 접촉음, 의자와 카메라 반응은 각각 물리적으로 검사한다. 감정 점수만으로 강제 책상 타격 금지.
5. 현장 첫 진입은 걸음 감속/간헐적 호흡/원거리 소음 감쇠/냉장고 모터음/최소 흔들림을 **동일한 공간 안에서** 제공하며 멀미 유발 연출 옵션을 끌 수 있게 한다.
6. 심문 얼굴 가리기는 '모델 품질 부족'을 가리는 수단이 아니며 동기 있는 카메라/조명 디자인. 손가락, 눈 주변, 턱의 움직임과 의자/컵의 미세 소리에 특히 집중한다.

### E. UI/UX

UI 콘셉트 이름: **EVIDENCE RESONANCE (증거 공명)**. 세계를 덮는 HUD가 아니라 손에 든 증거와 조사실의 유리/서류/테이블 등 실제 세계 표면에 연결된 얇은 정보 층. 새로운 자료를 제시하는 순간 두 개의 시간선/주장 조각이 짧게 겹치며 불일치 구간만 점진적으로 분기한다. 거짓말 확률, 용의자 감정 점수, 범인 마커는 표시하지 않는다. 질감·소리·정보 계층을 한국인 인지 특성과 한글 가독성에 맞춰 설계하고 사용자 연구 전에는 Steam에 없다고 단정하지 않는다. 자막, 색각 이상 모드, 흔들림 감소, 폰트 크기, 사용자가 닫을 수 있는 정보 패널 필수.

### F. 병합 우선순위 & 품질 게이트

P0: 기존 코드/에셋 인벤토리와 백업, AI 지식 누출 0개 재현 테스트, 사건 정본 불변, 1차 Python 테스트.
P1: 실제 Unity 조사실 1장면(리깅된 NPC 손·의자·컵·테이블)+용의자 대사→모션 제안→서버 검증→타격 프레임 물리 사건→30초 녹화.
P2: 302호 1인칭(손+증거 잡기/회전+공간 사운드+적절한 진입 연출) 실제 씬.
P3: 플레이어 조사→증거 제시→AI 반응→독립 NPC 행동→수사 가능한 흔적→첫 추론까지 12~15분 플레이.
P4: 조명/텍스처/애니/사운드/프레임타임 다듬기. 사건 002 확장은 P3·P4 만족 후.
