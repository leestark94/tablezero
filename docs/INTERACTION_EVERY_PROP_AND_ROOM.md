# CASE 001 302호 — 모든 공간과 사물에 손을 댈 수 있는 조사

## 현실적 기술 목표
프로젝트 내 **이미지에 실제로 보이거나 플레이 가능 공간 안에 배치된 모든 개별 소품**은 `prop_id`, `Collider`, `Inspect` 또는 `Open/Close/Move/Activate`, 장착 모델, 법적 접근 조건, 관찰 텍스트를 가져야 한다. 장식적인 벽·천장·바닥은 재질/반사/충돌/피격 흔적은 있지만 모두 서랍처럼 집는 대상은 아니다. 임의의 1px 얼룩까지 독립 물체로 만드는 약속은 하지 않는다

이번 패키지의 `data/room302_interaction_manifest.json`: 현관, 주방, 거실, 침구, 욕실, 복도 **140개 프로덕션 대상 사물**. 각각 고유 관찰 문장/행동 계약/내부 선반 접근 게이트/에셋 미배정 상태가 저장되어 있다. 140개는 개별 Mesh나 Prefab을 완성했다는 뜻이 전혀 아니다

## 실제 게임 루프
1. 1인칭으로 걸어가서 물체를 본다. 가까우면 호버 플래시 대신 손 반응/작은 포커스 텍스트만 발생
2. `E`: 조사, `길게 누르기`: 잡기/당기기/열기, `R`: 손에 든 물건 회전, `우클릭`: 가까이 보기 (프로젝트 Input System에 맞춰 매핑)
3. 서랍을 열 때 손이 손잡이를 잡는 접촉 프레임 → 실제 서랍 슬라이드 → 내부 물건 Collider 활성. 꺼낸 뒤에는 열린 서랍에 물건의 원래 위치 정보 보존
4. 화장실은 실제 연결 공간. 문을 열고 들어가 세면대·거울장·환풍기·변기·배수구·수건·칫솔까지 개별 조사
5. 증거 같아 보이는 물체도 즉시 ‘범인 확정’ 금지. 단서 후보(관찰) → 사진/지문/압수 절차 → 분석·교차검증을 분리
6. 물건을 뒤집거나 옮기면 그 **수사행동의 로그**를 남긴다. 부주의한 접촉은 감정용 자산을 손상시킬 수 있으나 플레이어에게 불합리한 숨은 확률 패널티는 금지
7. 임의의 3D 물체를 LLM이 생성하지 못하게 한다. AI는 사건 상태에 존재하는 prop_id와 그가 실제 본 물건만 언급할 수 있다

## 관찰과 정답의 경계
- 일반 사물: 고유한 표면·사용 흔적·위치·작동 여부를 볼 수 있으나 범행 관련성은 추론의 영역
- 증거 후보: 이미 정의된 `e02` 휴대전화, `e04` 배달 봉투, `e06` 머그컵 등 기존 CANON 앵커에만 연결. 관찰과 실제 확보는 **다른 행동**
- 감정 전: 혈흔 방향, 지문 주인, 시각, 사망 시각을 인터페이스가 ‘확정’으로 표시하지 않는다
- 출입/기기 기록: 현장 관찰 가능 물체와 공식 확보된 기록을 혼동하지 않는다. 통신 데이터 접근은 별도 절차

## 씬 제작 단위
각 영역에 ①수준 낮은 메시 배제 ②실측 ③Collider 레이어 ④3D 팔 IK ⑤손 접촉 AnimationEvent ⑥열림 뒤 내부 메쉬 ⑦상태 저장 ⑧소리 ⑨포커스 문구 ⑩20~40cm 확대 품질 승인 ⑪성능 프로파일을 통과한 프리팹만 배치

### 대표 조작
- 현관 도어락: 모델 애니메이션/버튼 신호와 열림 조건이 일치, 강제 조사 행동에는 합법적 접근 근거 필요
- 주방 냉장고: 문+냉동실 각각 열림, 음식 하나씩 관찰, 서랍/내부 씬 자체가 존재
- 침실: 이불을 들추면 아래 공간 실제 확인, 베개도 개별 회전, 서랍은 안쪽 수납 공간과 물건이 보여야 함
- 화장실: 문·변기 뚜껑·시트·수전·거울장·배수구·환풍기 개별 조작, 물/거울/표면반사 실제 게임 렌더
- 거실: 서류 더미를 넘기되 글이 읽히는 고해상도 텍스처 또는 Unity 텍스트 구성, 사진 프레임 뒷면도 확인
- 생활 쓰레기: 봉투·종이컵·휴지·배달용기 다수 물건. ‘자동 1회 조사’로 뭉뚱그리지 않는다

## 코드 연결
- `server/prop_world.py`는 허용 동작, 열린 수납함 선행 조건, 중복 실행, 공식 증거로의 무단 승격을 검증한다
- `unity/Runtime/TZInspectableProp.cs`는 `propId`와 인증된 모션/접촉/콜라이더 자리를 제공한다
- `unity/Runtime/TZPropFocusController.cs`는 실제 시야 Raycast 대상만 찾고 서버에 실행 요청을 제안한다
- `unity/Editor/TZPropCoverageAudit.cs`는 승인 없는 모델/중복 ID/바인딩 안 된 메시를 경고한다
- `tools/generate_room_catalog.py`를 수정하여 prop 목록 확장 가능. 기존 ID는 절대 함부로 바꾸지 않는다

## 필수 보완: 실제 클라이언트–서버 연결
이 패키지에는 140개 완성 Prefab과 302호 씬이 없다. Unity UI와 `PropWorld.interact`의 HTTP/게임 서비스 연결은 **직접 통합해야 한다**. 예제의 `authorized=True`는 서버가 플레이어의 씬 위치·권한·시야를 확인했다는 뜻이어야 하며, 사용자가 조작 가능한 클라이언트 boolean을 믿어선 안 된다. `asset_ready`도 검수 승인 데이터에서만 제공

## QA 재현 시나리오
- 서랍을 열지 않은 상태에서 안쪽 물건 조사 불가능
- 열린 냉장고에 카메라를 넣으면 내용물 개별 조작 가능
- 화장실 문을 열지 않고 안쪽 물건 Raycast 불가능
- 문/수전/슬리퍼/바닥 소리 각각 서로 다른 위치/재질과 일치
- 연출에 취해 카메라가 플레이어 조준을 강제로 빼앗지 않음
- 개별 prop 관찰로 canon 사건 정답 자동 노출 없음
- 100% 에셋 ID 매핑 상태여도 메쉬 품질/카메라 QA 미통과는 RELEASE_BLOCKED
