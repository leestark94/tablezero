# CASE DESK — 한국형 범죄 스릴러용 UI/UX 디자인 시스템 V10

## 독창성의 핵심: 선형 메뉴가 아니라 '기록의 신빙성'을 조작하는 행위
스팀의 흔한 코르크 수사보드·빨간 실 연결·네온 홀로그램·기술 데모풍 카드 레이아웃을 따라가지 않는다. 플레이어는 증거를 확보하고, 기록의 출처를 확인하고, 서로 다른 기록을 대조해 스스로 판단한다. 평소 시야를 가리는 HUD는 없다.

### 화면의 세 가지 상태

1. **현장 상태**: 손·동선·소리·현실 공간만 보인다. 눈에 띄는 것은 사건 맥락 텍스트 한 줄이 필요할 때뿐이다. `TAB`은 수사 기록을 여는 행동이다
2. **기록면 상태**: 화면 중심에서 관찰/기록/대조/판단을 진행한다. 카메라 동작과 충돌하지 않도록 플레이어 입력을 잠시 기록면으로 전환한다
3. **심문 상태**: 조사실의 인물 시선이 주인공이다. 질문·진술 기록은 손 닿는 메모나 테이블 모서리처럼 절제된 인터페이스로 제시한다. **기록면 전체를 강제로 항상 띄우지 않는다**

### 메뉴 정보 구조

- 사건 개요: 확인된 사건 배경과 수사의 기본 원칙
- 증거 보관함: 확보된 물증/기록만 표시. 취득·출처·시간·해석 한계를 상세로 제공
- 진술 기록: 검증되지 않은 Claim만 표시. 대사 뒤 마침표 금지. 질문 입력이 실제 심문으로 라우팅됨
- 시간 대조: 확보 기록을 시간 관점에서 검토. 확인되지 않은 시간은 추가하지 않음
- 수사보고서: 혐의 대상과 자료를 확인하고 4개 입증 축 기준으로 서버 평가. '정답 확인' 버튼이 아님
- 설정: 시점 움직임 축소, 한국어 자막, UI 크기. 실제 저장은 Unity 씬에서 검증 필요

### 실제 조작 규칙

- 자료 클릭: 오른쪽 상세에 제목/내용/출처/한계 표시. 정보가 없으면 빈 상태를 유지하고 임의 보완하지 않는다
- 자료 비교: 이미 확보한 증거 또는 실제 발생한 진술 기록 두 건만 사용자 선택으로 고정한다. 같은 자료 중복 고정 금지
- 자료 둘째 선택 시: 자동 빨간 균열·거짓말률·정답 마커 없음. 비교 문장과 근거만 제시
- 질문 제출: 실제 심문 준비 상태가 아니면 서버에서 거부. 질문 1회당 세계 시간이나 수사 자원 차감 금지
- 보고서 제출: 확인 버튼을 다시 눌러야 서버로 전달. 화면 효과로 결과를 미리 예고하지 않는다

### 토큰과 시각 흐름

- 베이스: 따뜻한 검정/차콜, 먼지 낀 그레이, 사용감을 지닌 브론즈 강조
- 상태는 색 하나에만 의존하지 않음. 텍스트와 위치를 함께 사용
- 본문 우선: 한국어 12–15px 기본, 상세 문서 텍스트 13–15px, 인지적 부담을 줄이는 행간
- 첫 화면에서 읽는 데 필요한 정보는 세 가지: 사건 이름 / 현재 페이지 / 선택 자료의 출처
- 마우스 입력 이징 기본 80–150ms, 패널 전환 200–400ms, 증거 보기 300–500ms를 후보로 실측 조정. 실제 구현된 animation이 없는 곳은 갑작스러운 반짝임으로 보완하지 않는다
- 화면 기준: 1920×1080 1차, 2560×1440 2차, ultrawide 21:9 3차. 글자가 작아지지 않도록 QA

### UI 개선을 실제로 검증하는 동영상

1. 현관 진입 중 UI가 시야를 가리지 않는 20초
2. CCTV 자료 열기 → 출처/한계 읽기 → 다른 실제 확보 자료와 비교 25초
3. 조사실 질문 → AI 답변 → 진술 기록 열기 → 다시 1인칭 심문 복귀 30초
4. 강압적 질문 후 부당한 절차 비용과 기록 변화가 결과에 반영되는 40초
5. 수사보고서 제출 전 확인 → 입증 부족/충족/오인 지목의 각 결말 비교

이 5개 연속 경험을 Unity에서 실제로 보여줄 수 없으면 **완료가 아니다**.

### 설계 원칙의 한계
코드와 HTML 프리뷰로는 화면의 아이디어와 조작을 볼 수 있지만, 사람 얼굴 모델/손 rig/소리/재질의 자연스러움, Unity C# 컴파일, 실제 UI 감성은 입증할 수 없다.
