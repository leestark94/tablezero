# CLAUDE CODE — TABLE//ZERO V0.4 심화 구현 명령

너는 《TABLE//ZERO》의 클라이언트/서버 아키텍트이자 실제 구현 책임자다. 기존 V0.3 폴더와 이 V0.4 업그레이드 팩을 모두 사용해 **CASE 001의 10~15분짜리 실제 플레이 구간**을 제작하라. 계획서만 쓰고 종료하지 마라. 단, 실제 개발 환경에 없는 자원이나 비밀 인증키를 추정하지 않고 단계별 현실적 한계를 명시하라.

## 1. 기존 파일을 실제로 열어라

- 이전 프로젝트: `TABLE_ZERO_AI_PROTOTYPE/README.md`, `server/app.py`, `web/index.html`, `data/cases.json`, `unity/*.cs`, `tests/*`.
- 추가 명세: `CASE001_CANON_LOCKED.json`, `docs/CASE001_VERTICAL_SLICE.md`, `docs/AI_ENGINEERING_SPEC.md`, `engine/simulator.py`, `tests/test_simulator.py`.
- 현재 Unity 프로젝트를 열 수 있으면 에셋·씬·렌더파이프라인·패키지를 조사하고 버전 관리 체크포인트를 만든다.

## 2. 1차 목표: AI보다 먼저 세계가 논리적으로 동작해야 한다

1. `CASE001_CANON_LOCKED.json`을 서버에서만 접근 가능한 진실 데이터로 사용. 클라이언트에는 일절 보내지 마라.
2. 기존 `server/app.py`의 질문 1회당 턴 차감 로직을 **인터뷰 세션 시작 시 1회 차감** 구조로 바꿔라. 확보한 증거를 조사실에서 제시하는 행동은 별도 자원을 사용하지 않는다.
3. 범인 AI가 공개되지 않은 경찰 증거 확보 사실을 자동으로 아는 문제를 해결. `KnowledgePartition`과 정보 전파 근거를 관리해라.
4. 용의자가 요청하는 행동은 `ActionResolver`에서 전제조건/실행 결과를 검사; 'contact_acquaintance'는 실제 수신자의 기억을 바꾸고 플레이어가 조사할 흔적을 만든다.
5. 모든 AI 대사는 `ClaimLedger`에 이전 진술과 함께 남기고 `verified=false`로 취급. 모순을 찾아도 AI가 사건의 정답을 임의 변경하는 것은 금지한다.
6. 최종 입증은 4개 독립 축 검증으로 변경. 증거 3개를 임의 제출하는 방식 폐기.
7. 사건 데이터가 서로 어긋나면 데이터를 무단 덮어쓰지 말고 `migration_notes.md`에 수정 이유와 이전/이후를 적어라.

## 3. 2차 목표: 진짜 LLM 연결 테스트

- Preview 모드는 AI가 아니라는 표시 유지.
- Ollama 또는 설정된 유료 API가 있으면 실제 응답과 기계 판정을 **구분해서** 테스트.
- 컨텍스트에 사건 전체 진실을 넣지 말고 해당 NPC가 아는 사실과 이전 대사만 전달.
- 구조화 출력은 현재 서비스 문서 기준으로 구현하고 서버에서 허용 ID·형태·상태 전제조건을 다시 검증.
- 정답 유출 시도, 질문 반복, 한국어 욕설 과용, 허위 목격 생성, 긴 대화에서 기억 소실, 타임아웃·중복 이벤트 등을 검사.
- 사용자의 명시적 승인 없이 유료 요청을 시작하지 마라.

## 4. 3차 목표: Unity 1인칭 플레이 구현

- **현장**: 한국 2010년대 오래된 빌라 302호+복도+계단. 한국 생활공간 느낌을 해치는 외국식/로우폴리 에셋 금지.
- **조사실**: 용의자가 플레이어 맞은편 실제 의자에 앉아 있는 1인칭 1:1 시점. 초상화 팝업이 메인이 되면 실패.
- **모션**: 키보드 질문·증거 제시에 반응해 `still`,`cup_touch`,`hand_stop`,`look_down` 등 짧고 세밀한 몸짓 재생. 없는 모션을 재생한 것처럼 허위 보고 금지.
- **미래형 UI**: 공간을 가리지 않는 절제된 HUD. 증거를 테이블 위에 올리면 작은 반응형 분석 레이어가 물리 오브젝트에 정합되어 나타남. 한글은 실제 TextMeshPro/UXML로 출력.
- **연출**: 현실적인 방·조사실과 조명 중심. 0.18~0.55초 전환, 침묵·호흡·의자 소리, 조건부 카메라 컷; 과장된 네온과 가짜 거짓말 확률 금지.
- **재현성**: 첫 15분에 최소 2번의 서로 다른 플레이 경로를 실제로 보여줘라.

## 5. 실행 테스트 순서

1. `python -m unittest discover -s TABLE_ZERO_V04_CASE001_DEEP_DIVE/tests -v` → 현재 예제의 15개 테스트 통과 확인.
2. 기존 V0.3의 테스트와 신규 테스트를 모두 통과하게 변경.
3. API 접속이 허용된다면 동일한 사건 시드로 20턴 × 30세션 등 품질 검사 수행.
4. 실제 Unity Play Mode 실행: 현장 탐색 → 증거 2개 확보 → 강도현 조사 → 이서연 조사 → 범인 자율행동 1회 → 타임라인 업데이트.
5. 화면 녹화 또는 스크린샷과 실행 로그를 전달. Unity Editor가 없는 환경이면 테스트하지 못했다고 명시.

## 6. 실패 처리

- AI 호출 실패는 같은 세계 상태로 재시도 가능. 성공하지 않은 행위로 자원 차감 금지.
- 사용자의 자유질문에서 시스템 메시지 탈취·비밀 정답 출력 시도가 들어오면 서버 권한을 우회하지 못하도록 점검.
- 범인 AI가 사실을 '주장'하는 것과 게임의 실제 세계가 변하는 것은 구분.
- 이벤트가 실제로 적용되지 않았으면 '범인 자율행동 구현 완료'라고 보고하지 마라.

## 7. 최종 납품 보고서

- 실제 변경 파일명과 코드 위치, 신규 테스트 결과.
- 'AI 자유 대화 20턴' 실제 로그, 발화의 일관성 검증.
- '범인이 선택→서버 검증→실제 게임 상태 변경→플레이어가 발견'의 **재현 가능한 최소 3개 로그**.
- 현장 1인칭, 조사실 1:1, 증거 제시 장면의 실제 Unity 화면.
- 완료/미완료/차단 사유를 구분.

**목표는 5개 사건 개요를 더 많이 쓰는 게 아니다. CASE 001에서 플레이어가 실제 AI와 수사전략을 겨루는 경험을 완성하는 것이다.**
